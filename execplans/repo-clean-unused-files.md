## Purpose / Big Picture

After this change, the repository should contain only files and folders that are part of the current pnpm/Turborepo codebase, active workspace implementations, or intentional project metadata. A contributor can verify the cleanup by checking that the deleted paths are either regenerated by tooling when needed or are no longer referenced anywhere in the repository, then running the standard validation commands to confirm the monorepo still builds and type-checks.

## Context and Orientation

This repository is a pnpm-managed Turborepo with application workspaces in `apps/api-new` and `apps/web-new`, plus shared packages in `packages/*`. The root contains both source-of-truth project files (`package.json`, `pnpm-workspace.yaml`, `turbo.json`, `README.md`, `AGENTS.md`, `PLANS.md`) and local/generated artifacts created by development tools.

For this cleanup, "unused" means one of four things:

First, generated artifacts that are already ignored and can be recreated by tooling, such as `node_modules`, `.turbo`, `.pnpm-store`, and Docker prune output in `out/`.

Second, stale repository files whose contents still point at removed paths or superseded structure, such as editor settings that reference `apps/web` instead of `apps/web-new`.

Third, orphaned project files that are not imported, routed, exported, or otherwise referenced by any active source or configuration.

Fourth, empty leftover directories that no longer contain tracked source files.

The current repository state is already dirty because earlier migration work changed many files. This cleanup must therefore avoid reverting or touching unrelated edits and should delete only paths that are independently justified by current repository references.

## Plan of Work

First, confirm candidate deletions with repository searches. For root artifacts, use `.gitignore`, Dockerfiles, and package scripts to prove which directories are generated rather than source. For source files inside `apps/*` and `packages/*`, verify whether each candidate is imported from any active module, route table, or package export. For assets, search for both the filename and the public URL path.

Second, remove only the confirmed unused paths. Delete generated folders at the repository root, stale editor metadata under `.vscode`, orphaned assets such as any unreferenced image files, and empty source directories. Keep all active package manifests, contracts, database migrations, and workspace code that participates in the current pnpm/Drizzle architecture.

Third, rerun validation from the repository root to confirm that deleting these paths did not break imports, route registration, builds, or workspace type-checking.

Because deleting `node_modules` removes the local toolchain needed to execute workspace scripts, run validation before the final cache/install-directory purge. After validation succeeds, remove generated directories last.

## Idempotence and Recovery

Deleting generated directories is idempotent because the package manager and Turbo recreate them as needed. Deleting stale editor metadata or orphaned assets is also safe when repository searches confirm no references remain. If a deletion turns out to be needed, recover it with `git checkout -- <path>` for tracked files or by regenerating the artifact with the appropriate tool for ignored/generated directories.
